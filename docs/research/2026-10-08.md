### 補足：`requirements.txt` は「固定なし」ではなく下限つき

- 実際の中身は `line-bot-sdk>=3.11`（下限あり・上限なし）。Render は再ビルドのたびに、その時点の最新版（今なら 3.26.0）を入れる可能性が高い（推測。Render のビルドログは会社から見えない）。
- 最新版は **Python 3.10 以上が必要**。本番の Python の版はリポジトリに書かれていない（`runtime.txt` や `.python-version` はない）ので未確認。もし 3.10 未満なら、pip は条件に合う古い版を選ぶ（pip の一般的な動き。どの版になるかは未確認）。その場合も `UnsendEvent` の有無は別途確認が要る。
- 将来 4.x が出ると、上限がないため自動で入り、import 名が変わって起動しなくなる危険がある（推測）。

## 2. 副テーマ：長文の分割（バックログ候補7）の判断材料

### 2-1. テキストメッセージの文字数上限

- **公式ドキュメント（LINE Developers の Messaging API リファレンス）は今日読めず、未確認。**
- 第三者（Infobip の LINE 連携ドキュメント）は、LINE のテキストを空白込みで「limited to 5,000 characters」と書いている。**二次情報**。
- 別の第三者（Zaapi）のページは1,000文字としているが、文脈から同社サービス側の制限と読める（推測）。LINE の仕様の根拠にはしない。

### 2-2. 1回の応答（reply）で送れるメッセージ数の上限

- **未確認。** 公式リファレンスも、送信の説明ページ（sending-messages）も今日は読めなかった。第三者の資料でも件数を明記したものは見つけられなかった。
- 参考：今の `reply()` は1回の応答で **TextMessage を1件だけ** 送っている（`main.py` を読んで確認）。分割する場合は件数の上限が効いてくるので、実装前に公式で確かめる必要がある。

### 2-3. 今の `main.py` で上限を超えうるか（見立て。推測を含む）

- AI の返事は `max_tokens=400` で打ち切られる。日本語では1トークンがおおむね1〜数文字なので、返事は多くても千数百文字程度に収まり、5,000文字（二次情報の値）に届く可能性は低い（推測。トークンあたりの文字数は確認していない）。
- `PERSONA` は「2〜4文」の短い返事を指示している。普段はさらに短い（推測）。
- 固定文（`HELP_TEXT`、`BURN_REPLY`＋応援リンクなど）は人が書いた短い文で、上限に近いものはない。
- **結論（推測）：今の設定のままなら、長文の分割は急ぐ必要がない。** `max_tokens` を大きく増やす変更をするときに、あわせて考えればよい。

### 2-4. 調べる途中で気づいた、文字数より起きやすそうな点（コードを読んでの指摘。影響は未確認）

- AI の返事が空（テキストのブロックがない、または空白だけ）だと、`answer` が空文字のまま `TextMessage(text="")` を送ることになる。LINE は空のテキストを受け付けない可能性が高い（推測。公式の最小文字数は今日は未確認）。その場合 `reply` が例外を出し、利用者には何も返らない。
- `reply()` の呼び出しは try で囲まれていないので、LINE 側でエラーになると、その例外は `/callback` まで上がる（コードを読んで確認。そのとき LINE に何が返り、再送されるかは未確認）。
- 長文の分割より先に、「返事が空なら、決まった短い一言に差し替える」程度の守りの方が小さく効く可能性がある（推測）。

## 会社への示唆（3つ以内）

1. **`UnsendEvent` が公開版にあるかは、今日も未確認。** PyPI の最新は 3.26.0（2026-09-29、Python 3.10 以上が必要）と分かったが、配布ファイルの中身は読めなかった。会社の調査ではこれ以上進めにくいので、オーナーに「デプロイログの版番号と ImportError の有無」か「手元での1行の import 確認」をお願いし、それまで LINE SDK に新しく依存する変更は重ねない方針を続ける。
2. **`requirements.txt` の `line-bot-sdk>=3.11` には上限がない。** オーナーの確認で動く版が分かったら、`line-bot-sdk>=3.xx,<4` のように上限（と、`UnsendEvent` が確かにある版を下限）にする案を企画部で検討する価値がある（4.x で import 名が変わって突然起動しなくなるのを防ぐ。推測）。本番の Python の版もあわせてオーナーに見てもらう。
3. **候補7「長文の分割」は急がなくてよい（推測）。** `max_tokens=400` と「2〜4文」の指示では、二次情報の上限 5,000 文字に届きにくい。1回に送れる件数は未確認のまま。それより「AI の返事が空なら決まった一言に差し替える」守りの方が小さく効く可能性があるので、候補として検討してほしい（LINE SDK に新しく依存しない）。
