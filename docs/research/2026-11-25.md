# 調査メモ 2026-11-25：運営費を減らす手としての「プロンプトキャッシュ」は焚き火で効くか ― Anthropic の公式仕様（最小の長さ・料金・保存のされ方）と、LINE の応答メッセージの通数の再確認

調査部。これまでの調査とバックログを「キャッシュ」「cache_control」で検索して、一度も扱っていないことを確かめてからこのテーマを選んだ（`main.py`・`docs/` のどこにも出てこない）。運営費はオーナーが払っている（CLAUDE.md）。11-20 にモデルの料金は調べたが、同じ指示文（`SYSTEM_PROMPT`）を毎回送っている分を安くする仕組みは見ていなかった。あわせて、運営費のもう半分である LINE の通数について、返事（応答メッセージ）が今も通数に数えられないかを公式で確かめた。
相談窓口の確認は 11-28 ごろの予定なので今日はしていない。コード・git は触っていない。

## 要点

1. **今の既定モデル Haiku 4.5 では、プロンプトキャッシュは効かない見込みが高い**。Haiku 4.5 でキャッシュされるのは 4,096 トークン以上の入力だけ（公式）。焚き火の指示文（PERSONA＋SAFETY）は約1,200字で、4,096 トークンには遠く届かない（調査部の見積もり、推測）。短すぎる場合はエラーにならず、**黙ってキャッシュされないだけ**（公式）。
2. **Haiku 5.5 に移ると最小の長さは 512 トークンになり、指示文だけでもキャッシュできる見込み**（公式の表＋調査部の見積もり）。ただし Haiku 5.5 はもともと入力が 100万トークンあたり 0.10 ドル（11-20 の調査）なので、減る額はごく小さい（下の 3 の試算、推測）。
3. **LINE の返事（応答メッセージ）は今も通数に数えられない**（LINE 公式の料金ページと、2026-05-28 の公式ブログ）。焚き火は返事しか送っていないので、LINE 側の通数の費用は今のところ増えない。
4. **キャッシュの中身は Anthropic のメモリに最短5分残る**（公式）。会話まで含めてキャッシュすると、「燃やす」のあとも Anthropic 側のメモリに少なくとも5分残りうる。今の `HELP_TEXT` の「通常は30日以内に削除」の説明と食い違うほどではないが、約束1の向きとは逆の動きが増える（調査部の見立て）。
5. **SAFETY の要修正：なし**（今日は窓口を調べていない。読んだ資料に窓口の情報はない）。

## 1. プロンプトキャッシュの公式仕様（Anthropic）

出典A（公式ドキュメント「Prompt caching」の Markdown 版）で確かめたこと：

### 1-1. キャッシュされる最小の長さ（モデルごと）
| 最小トークン数 | 該当するモデル（焚き火に関係するものだけ） |
| --- | --- |
| 4,096 | **Haiku 4.5**（今の既定値 `claude-haiku-4-5-20251001`） |
| 512 | **Haiku 5.5**（11-20 に調べた移行先） |

- 最小に届かない入力は、**エラーを返さずにキャッシュなしで処理される**。キャッシュされたかは返事の `usage` の `cache_creation_input_tokens`・`cache_read_input_tokens` が両方0かどうかで分かる。[出典A]
- 第三者の記事も、最小未満は黙って効かないと注意している（第三者、根拠にはしない）。[出典D]

### 1-2. 料金の倍率（元の入力単価に対して）
- 5分のキャッシュの書き込み：1.25倍。1時間のキャッシュの書き込み：2倍。読み出し（ヒット）：多くのモデルで0.1倍。キャッシュの区切りの指定そのものは無料。[出典A]
- 元の単価（11-20 の調査で公式の料金表から確認済み）：Haiku 4.5 は入力1ドル・出力5ドル、Haiku 5.5 は入力 0.10ドル・出力 0.50ドル（100万トークンあたり、入力10万トークン以下）。[`docs/research/2026-11-20.md`]
- 今日、公式の料金ページ（出典E）を直接読もうとしたが、取得の許可が下りず読めなかった。上の単価は 11-20 の確認のまま。

### 1-3. 長さ・使い方
- 既定の寿命は5分で、使うたびに延びる（追加料金なし）。1時間の寿命は追加料金で選べる。[出典A]
- 指示文（`system`）にだけ印を付けて、会話は含めない使い方ができる。リクエストの一番上に1つ指定すると、会話の最後まで自動で区切りを動かす「自動キャッシュ」もある。[出典A]
- 指示文のどこか1字でも変わるとキャッシュは作り直しになる（完全一致が条件）。thinking の設定を変えたときも無効になりうる。[出典A]
- キャッシュは返事の中身を変えない。[出典A]

### 1-4. 保存のされ方（約束2との関係）
- 公式は、プロンプトの文そのものも Claude の返事も保存しないと説明している。キャッシュとして持つのは計算用の中間データ（KV キャッシュ）と暗号的なハッシュで、**メモリにだけ置き、ディスクには保存しない**。寿命（5分か1時間）が過ぎたら速やかに消すが、**ぴったりその時に消えるとは限らない**。[出典A]
- 別の組織とはキャッシュを共有しない（同じ文でも）。[出典A]
- ゼロデータ保持（ZDR）の対象にもなる、と書かれている（焚き火が ZDR の契約をしているかは会社から見えない）。[出典A]

## 2. 焚き火に当てはめると（`main.py` を読んだ範囲＋推測）

- `answer_and_reply()` は毎回 `system=SYSTEM_PROMPT` を文字列で渡し、キャッシュの指定はない（348〜353行）。`SYSTEM_PROMPT` は PERSONA（46〜61行）＋ SAFETY（66〜71行）。
- 指示文の長さ：調査部が行ごとに数えた概算で**約1,200字**（推測。正確な数は数えていない）。日本語は1字が1トークン前後になることが多いので（推測）、Haiku 4.5 の 4,096 トークンには届かない見込み。会話の履歴（`MAX_TURNS = 20`）を足すと、長い会話の終わりのほうだけ 4,096 を超えることはありうる（推測）。
- **Haiku 4.5 のまま指示文にだけ印を付けても、黙って何も起きない見込み**。料金は下がらず、テストでは効いたか分からない（`usage` を見るしかないが、本番の返事は会社から見えない）。
- **Haiku 5.5 に移った場合の試算（推測）**：指示文が約1,200字→ Haiku 5.5 の数え方（同じ文が約3割多い、11-20）で約1,500〜1,600トークンと仮定。1回の呼び出しで指示文の分は約0.00016ドル。キャッシュが毎回当たったとしても減るのはその9割、1回あたり約0.00014ドル。**1か月に1,000回呼んでも約0.14ドル（20円ほど）**。しかも5分以内に誰かが話しかけないとキャッシュが切れ、書き込みの1.25倍がかかる。利用者が少ない時間帯はむしろ少し高くなりうる。
- **会話まで含める自動キャッシュは選ばないほうがよい（調査部の見立て）**：会話の中身が Anthropic のメモリに最短5分残り、「燃やす」で焚き火のサーバーから消したあとも、その間は残りうる。今の `HELP_TEXT`（161行）は「Anthropic 社に送られ、通常は30日以内に削除」と書いているので嘘にはならないが、約束1の向きに逆らう動きをわざわざ足すことになる。
- **テストとの関係**：11-04 の「Claude の呼び方を見張るテスト」は `messages.create` の引数が4つだけであることを見ている（バックログの記録）。キャッシュを入れる日はこのテストを同じ差分で直す必要がある。`system` を文字列からブロックの一覧に変えることになり、SAFETY の中身は変えなくても SAFETY を渡す形を変えるので、安全審査部の確認が要る（調査部の見立て）。

## 3. LINE の通数（応答メッセージ）

- LINE 公式の「Messaging API の料金」ページは、通数に数える送り方をプッシュ・マルチキャスト・ブロードキャスト・ナローキャストの4つとし、**応答メッセージは数えない**送り方として示している。通数は送る相手の人数で数え、1回に入れる吹き出しの数は関係しない。ブロックしている人への送信も数えない。[出典B]
- LINE Developers の公式ブログ（2026-05-28）も、応答メッセージは通数に含まれないと説明している。[出典C]
- 焚き火が LINE に送るのは `reply_message`（応答メッセージ）と、初期オフのローディング表示だけ。返事の通数の費用はかからない。**ローディング表示が通数に数えられるかは、今日見た2つのページにも書いていない**（11-16 の結論と同じ。変わらず未確認）。
- 推測：Webhook の2秒の問題（候補欄）を「先に受け取りだけ返して、あとからプッシュで返事を送る」形で直すと、返事が通数に数えられる送り方に変わり、オーナーの費用が増える。非同期化を検討する日は、プッシュではなく応答メッセージ（返信用トークンの期限内）で返す形を前提にしたほうがよい。

## 確認できなかったこと

1. 焚き火の指示文の正確なトークン数（数える API を使っておらず、文字数も概算）。4,096 に届かないことは、概算と最小値の差が大きいので確度は高いと見ているが、数字で確かめてはいない。
2. 本番の1日の呼び出し回数・会話の長さ・利用者の時間帯（会社から見えない）。上の費用の試算は仮の回数での計算にすぎない。
3. 公式の料金ページ（出典E）と、旧ドメインの「Prompt caching」ページ（出典F）は取得の許可が下りず読めなかった（くり返していない）。同じ内容は出典A（新しいドメインの Markdown 版）で読めた。
4. 焚き火の Anthropic のアカウントが ZDR の契約をしているか（オーナーにしか分からない。ただし今日の結論には関係しない）。
5. ローディング表示が通数に数えられるか（11-16 から未確認のまま）。

## 会社への示唆

1. **企画部へ：プロンプトキャッシュは今は候補にしない。** Haiku 4.5 では最小の長さ（4,096 トークン）に届かず、黙って効かない見込みが高い。Haiku 5.5 に移ったあとでも減るのは月に数十円の規模（推測）で、`messages.create` の形を変える・テストを直す・安全審査部の確認が要るのに見合わない。候補欄に「調べた結果、今はやらない」と1行残しておくと、同じ調査をくり返さずにすむ。
2. **企画部へ（移行の日の材料）：もしキャッシュを入れる日が来ても、指示文（`system`）だけにし、会話は含めない。** 自動キャッシュは会話を Anthropic のメモリに最短5分残すので、約束1の向きに逆らう。「既定のモデル Haiku 4.5 の廃止に備える」の項目に添える材料として使える。費用を減らしたいなら、まず Haiku 5.5 への移行そのもの（11-20、入力の単価が10分の1）のほうがずっと効く（推測）。
3. **企画部・広報部へ：LINE の返事は今も無料（通数に数えない）。** 非同期化（Webhook の2秒）を考える日は、プッシュで送ると費用が発生することを前提にする。広報部は「完全無料で運営」「費用ゼロ」などとは書かない（AI の費用はオーナーが払っている）。
