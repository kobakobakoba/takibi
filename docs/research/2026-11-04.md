## 3. API の新しい版「2026-10-21」と Python SDK 2.0（新しく分かったこと）

### 3-1. 事実

- **API の版**：10-21 に「2026-10-21」が出た。Messages API では、`temperature`・`top_p`・`top_k` を送ると既定値でも 400 エラー、`assistant` 側の document ブロックや `user` 側の text ブロックの citations も 400、など（公式の移行ガイド）。
- **版の選ばれ方**：SDK は、その SDK の大きな版が出たときの最新の API の版を送る。**Python SDK は 2.0.0 から「2026-10-21」を送る**。それより前の SDK は「2023-06-01」を送る（同ガイド）。
- **古い版「2023-06-01」の終わり**：公式の版のページ・移行ガイドとも**終了日の記載なし**。同じ版の中では既存の入力・出力の項目を保つ、と書いてある。
- **SDK 2.0 のおもな変更**：API キーを `Authorization: Bearer` で送る、1つのクライアントは1つの認証情報だけ持つ（`api_key` と `auth_token` を両方渡すとエラー）、`MessageParam` の型を役ごとに分けた、Text Completions の削除、ライセンスが MIT から Apache 2.0 へ、など（移行ガイド、解説記事、GitHub の issue）。リリースは 10-21（GitHub のリリースページ）。Arch Linux のパッケージは 11-02 に 2.4.0 で更新されていた。
- **SDK 1.0（2026-08-20）の変更**：Python 3.10 以上が必要、HTTP の部品を `httpx` から `httpx2` に変更、Messages の関数から `temperature` などを削除、など（解説記事、GitHub の issue）。
- **Render の Python**：PYTHON_VERSION も `.python-version` もなければ、サービスを作った日の既定の版になる（2025-06-12 以降に作ったサービスは 3.13 以上）。焚き火のリポジトリには `.python-version` がない（確認済み）。焚き火のサービスを作った日と、環境変数の設定は会社から見えない。

  - 上の呼び方は SDK 1.x・2.x の解説で「壊れる」とされた項目に当たらないので、**動き続ける可能性が高い**。ただし公式の変更履歴を全部は読めておらず、確かめてはいない。
