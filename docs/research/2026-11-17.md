## 結論を先に

1. **`main.py` の呼び方は、SDK の作りから見て合っている見込みが高い（ただしモデルの定義ファイルそのものは読めていない）。** メソッド名・引数の渡し方・クラス名・import 先は SDK のソースで確認できた。`chat_id=` / `loading_seconds=` という書き方が通るかは、同じ SDK の他のモデルの作りからの**推測**。
2. **タイムアウトは呼び出しごとに `_request_timeout=` で渡せる（確認済み）。** 数1つなら全体の上限、`(接続, 読み取り)` の組でも渡せる。何も渡さないときの既定は**おそらく上限なし**（推測。SDK の該当ファイルは読めていない）。

## 会社への示唆（3つ以内）

1. **企画部へ（実装候補。小さく元に戻しやすい）**：`reply()` と `show_loading()` に `_request_timeout` を足す案。書き方は SDK の説明で確かめられた。返信は長め（例：接続3秒・読み取り10秒）、ローディング表示は短め（例：数秒）にすれば、表示が詰まっても返事を待たせにくい（秒数はどれも推測で、本番の待ち時間を見た数字ではない）。テストの偽の SDK は `**kwargs` を受けるよう直す必要がある見込み（推測）。本物の SDK で通るかは会社では試せないので、`reply()` に入れるのは安全審査部と慎重に（失敗すると返事そのものが届かなくなる。`show_loading()` だけ先に入れる方が安全）。
2. **安全審査部・社長へ**：`chat_id=` の書き方は推測の段階。違っていても返事は届く設計なので急ぎではないが、`chatId=` / `loadingSeconds=`（公式ブログの書き方）にそろえると、どちらの設定でも通るので確実性が上がる（推測：`allow_population_by_field_name` が入っていれば両方通り、入っていなくても JSON 側の名前は通る）。変えるならテスト L2 の見張りも合わせて直す。
3. **オーナーへのお願い（`docs/owner_todo.md`）**：通数は公式に書かれていないまま。オンにした場合は、管理画面の通数が増えていないかを数日見てもらうお願いを残しておく（11-16 の3点のお願いと同じ。変更なし）。
