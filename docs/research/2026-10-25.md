# 調査メモ 2026-10-25：Claude Messages API は利用者の発言が2つ続く形を受け付けるか（返信失敗時の文脈・案(ii)の宿題）／main.py の API 呼び出しの点検

調査部。テーマは社長指定。10-23 の安全審査部の事前意見で宿題になった「同じ役（user）の発言が2つ続く形を API が受け付けるか」を Anthropic 公式ドキュメントで確かめ、`main.py` のモデル名と API 呼び出し部分を読んで関係する点を書く。コードは変更していない。

**結論を先に：公式の API リファレンスに、同じ役の発言が続いた場合は1つの発言にまとめて扱う、と明記されている。エラーにはならない扱いで、開発部が「前の発言とつなげる」処理を足す必要はない。** ただし、まとめるときの具体的なつなぎ方（区切りの入れ方など）は書かれていない。

## 1. 公式ドキュメントで確かめたこと（事実）

### 1-1. Messages API リファレンス（`messages` パラメータの説明）

- モデルは user と assistant が交互に並ぶ会話で学習している、と書かれている。
- そのうえで、リクエストの中で user（または assistant）の発言が続いた場合は「will be combined into a single turn」（1つの発言にまとめられる）と明記されている。
- 最後の発言が assistant の場合は、その続きから返事を書く（prefill）。prefill に対応していないモデルでは 400 エラーになる、とも書かれている。
- 出典：https://platform.claude.com/docs/en/api/messages/create （docs.claude.com の API ページは platform.claude.com へ転送される）

### 1-2. 「Using the Messages API」ガイド

- 同じ役が続く場合については触れていない（交互でなければならないとも書いていない）。
- API は会話の状態を持たず、毎回これまでの会話を全部送る作りであることの説明がある。
- prefill は Claude 4.6 以降のモデル（と Mythos Preview）では使えず、400 エラーになると書かれている。
- 出典：https://platform.claude.com/docs/en/build-with-claude/working-with-messages

### 1-3. エラーの説明ページ

- 同じ役が続く形、先頭が user でない形についてのエラーは載っていない。
- 載っているのは prefill の 400 エラーで、エラー文には会話は user の発言で終わる必要がある旨が書かれている。
- 出典：https://platform.claude.com/docs/en/api/errors

### 1-4. 確かめられなかったこと

- まとめるときの具体的なつなぎ方（2つの発言の間に区切りが入るか等）。公式ドキュメントには書かれていない。モデルからは「2つの発言を1回分として読む」形になると考えられる（推測）。
- 先頭の発言が user でなければならないか。リファレンスには書かれていない（`main.py` は先頭を user にそろえているので、今は問題にならない）。

## 2. `main.py` の API 呼び出しを読んで分かること（コードを読んで確認）

### 2-1. 呼び出しの形

- モデル：`MODEL = os.environ.get("CLAUDE_MODEL", "claude-haiku-4-5-20251001")`（31行）。環境変数 `CLAUDE_MODEL` があればそちらが使われる。本番で設定されているかは会社から見えない。
- 呼び出し：`claude.messages.create(model=MODEL, max_tokens=400, system=SYSTEM_PROMPT, messages=to_send)`（295〜300行）。指示は先頭の `system` 欄で渡し、`messages` には user／assistant だけが入る。`temperature` などは使っていない。
- `to_send` は、その回の利用者の発言を履歴の最後に足してから写すので、**送る会話は必ず user で終わる**（274・279行）。先頭も user にそろえている（277〜278行）。prefill の形にはならない。

### 2-2. 同じ役が続く形は、今の作りでもすでに起こりうる（推測を含む）

- 返事を待っている間に同じ人が次の発言を送ると、1つ目の返事が履歴に入る前に2つ目の発言が足されるので、2つ目の呼び出しでは user が2つ続いた会話を送る（274〜279行と 316〜325行の順番から）。その後、返事が2つ続けて履歴に入るので、assistant が2つ続く形もできる。
- つまり「続く形」は案(ii)で初めて生まれるものではなく、連投のときにはすでに送っている。本番でエラーになっているかは、ログが会社から見えないので分からない。公式の説明（1-1）どおりなら、まとめて扱われてエラーにはならない。

### 2-3. 案(ii) に当てはめると

- 案(ii)（届かなかった AI の返事だけ外し、危ない言葉が当たった利用者の発言は残す）では、次に送る会話が「…、残した発言（user）、新しい発言（user）」になる。公式の説明では1つの発言にまとめて扱われるので、**API の受け付けの面では追加の処理なしで成り立つ**。
- 開発部が「前の発言と1つにつなげる」処理を足す必要は、API の受け付けのためにはない（差分が増えずに済む）。つなげ方を自分で決めたい理由が別にあれば別の話（推測）。
- 残る1点：モデルが2つの発言を1回分として読んだとき、前の発言（例：「死にたい」）に受け止め直すかどうかは、ドキュメントでは確かめられない（推測。会社から本番の返事は見えない）。安全審査部の判断材料として残す。

## 3. あわせて見つかった、モデルと SDK の注意点

### 3-1. 既定のモデル `claude-haiku-4-5-20251001` の状態

- モデル廃止のページでは、今も **Active（使用可）**。非推奨（Deprecated）の日付は N/A。ただし「廃止予定日」は **2026年10月15日以降** と書かれており、その日はすでに過ぎている。廃止の告知の履歴に Haiku 4.5 は載っていない。
- 同ページによれば、公開モデルの廃止は少なくとも60日前に、使っている人へメールで知らせる。廃止後のモデルへのリクエストは失敗する。
- Haiku 4.5 の紹介ページでは「legacy」扱いで、Haiku 5.5 への移行を勧めている。
- 焚き火への影響（推測）：廃止されると Claude の呼び出しが毎回失敗し、すべての発言に「おわび」が返るようになる。告知は Anthropic のアカウントのメールに届くはずで、会社からは見えない。
- 出典：https://platform.claude.com/docs/en/about-claude/model-deprecations 、https://platform.claude.com/docs/en/models/haiku-4-5/overview

### 3-2. 料金（参考。モデルを変える提案ではない）

- 料金表では、Haiku 4.5 は入力 $1／出力 $5（100万トークンあたり）、Haiku 5.5 は 10万トークン以下の入力なら入力 $0.10／出力 $0.50。焚き火の1回の入力は 10万トークンよりずっと小さい（推測。履歴は20発言まで）。
- 料金の面では「高いモデルに変える」には当たらない。ただし返事の口調や安全の案内の出方が変わりうるので、変えるならオーナー判断＋安全審査部の審査が要る（推測）。
- 出典：https://platform.claude.com/docs/en/about-claude/pricing

### 3-3. API の新しい版（2026-10-21）と `requirements.txt`

- 2026-10-21 版では `temperature`・`top_p`・`top_k` を送ると 400 エラーになる。assistant 発言に文書を入れる・user 発言に引用情報を付けるのも 400。**`main.py` はどれも使っていない**。同じ役が続く扱いや prefill の扱いの変更は、このページには書かれていない。
- SDK を使う場合は、SDK の大きな版が出た時点の API 版が使われ、Python では `anthropic` 2.0.0 から新しい版になる、と書かれている。API キーの送り方も変わる（ヘッダーが変わる）。
- `requirements.txt` は `anthropic>=0.40` で上限がないので、本番を作り直したときに 2.x が入りうる（推測。PyPI の最新版のページは今日は取得できず、2.0.0 が公開済みかは未確認）。辞書で渡す今の書き方なら変更は要らないとページにある。
- 出典：https://platform.claude.com/docs/en/api/migration-2026-10-21

## 会社への示唆（3つ以内）

1. **案(ii) の API 面の心配は解けた。** 公式リファレンスは、同じ役が続くと1つの発言にまとめて扱うと明記している。つなげる処理を足さずに案(ii) を作れるので、差分は小さいままで済む。残る判断は「モデルが残した発言に受け止め直すか」という中身の話だけで、安全審査部に回せる。
2. **「続く形」は連投のときにすでに送っている**（2-2）。案(ii) で新しい種類の送り方が生まれるわけではない、という点も審査の材料になる。
3. **既定のモデル Haiku 4.5 は、廃止予定日の「10月15日以降」を過ぎた。** 今は使用可で、廃止の告知はまだ出ていない（少なくとも60日前にメールで知らせる決まり）。オーナーに Anthropic からのメールを見てもらい、告知が来たら移行を検討する。あわせて `anthropic` の上限なしで 2.x が入りうる点も、line-bot-sdk の上限の件と一緒に考える（推測を含む）。
