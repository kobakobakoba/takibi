調査部。直近は 11-15（相談窓口の定期確認）、11-14（仕事と介護の両立者）、11-08〜11-12（当事者ニーズ）。当事者ニーズと窓口は続けて扱ったので、今日は**企画部が外部アカウントなし・SAFETY に触れずに作れる材料**を探した。これまでの調査を「ローディング」「loading」で grep したところ、扱った調査はなかった。

焚き火は、利用者の発言を受けてから Claude の返事を待ち、それから返信する（`main.py` 297〜298行・311〜316行、コードを読んで確認）。待っている間、利用者のトーク画面には何も出ない。LINE には、この間に「返事を準備中」のアニメーションを出す API がある。今日はその仕様と、焚き火に入れるときの条件を調べた。

## 結論を先に

1. **LINE 公式の機能で、1対1トークに限り、返事を待つ間のアニメーションを 5〜60 秒（5の倍数）出せる。** 送るのは利用者の ID と秒数だけで、会話の中身は送らない。返事が届くと自動で消える。
2. **今の `requirements.txt`（`line-bot-sdk>=3.11`）のままで使える。** この機能は Python SDK 3.11.0 で入った。ライブラリの追加も、新しい外部アカウントも、新しい環境変数も要らない（今のチャネルアクセストークンで呼べる）。
3. **見えない人がいる。** iOS・Android の LINE 13.16.0 以上だけが対象で、トーク画面を開いていないときは出ず、あとで開いても出ない。PC 版で出るかは公式に書いていない。成功の応答（202）はブロック中などで表示されないときも返るので、**本当に表示されたかは会社からは分からない。**
4. **通数（料金）に数えるかは、公式のどのページにも書いていなかった。** 料金ページが挙げる数える送り方はプッシュ・マルチキャスト・ブロードキャスト・ナローキャストの4つで、この API はそこに入っていない（数えないと言い切れる記述は見つけていない）。

## 2. Python SDK の版（`requirements.txt` のままで使えるか）

- この API は line-bot-sdk-python **3.11.0** で入った（リリースノート F、生成コードのコミット G）。追加されたのは `linebot.v3.messaging` の `ShowLoadingAnimationRequest` と、`MessagingApi.show_loading_animation()`。
- 焚き火の `requirements.txt` は `line-bot-sdk>=3.11` なので、本番にどの版が入っていても（3.x の範囲なら）このクラスはある。今の最新は v3.27.0（2026-10-27）で、この機能の削除や破壊的変更の記載はなかった（H）。4.x が出たかは確認できなかった。
- スタンプの一言の候補（候補欄）で問題になった「新しい import が本番の版にあるか」は、この機能では `>=3.11` が下限なので当たらない（ただし本番の実際の版は会社から見えない。オーナーの版確認のお願いは続いている）。
- テストの偽の SDK（`tests/test_main.py` 63〜77行）には `show_loading_animation` も `ShowLoadingAnimationRequest` もない。入れるなら偽物にも足す必要がある（コードを読んで確認）。

## 3. 約束・安全との関係（コード確認＋推測）

- **約束2（保存しない）**：送るのは利用者の ID と秒数だけで、会話の中身は送らない（仕様 A・B）。ID はもともと返信のたびに LINE に渡している。新しい保存先・ログは要らない。ただし失敗時の扱いは今の `reply()`（224〜225行、例外の種類の名前だけを出す）にそろえる必要がある（推測：例外の中身を出すと約束2の見張りテストに当たる）。
- **返事が遅れないか**：アニメーションの呼び出し1回ぶん、Claude を呼ぶのが遅れる。どれくらい遅れるかは測っていない（会社からは本番が見えない）。この呼び出しが失敗しても、返事（またはおわび）は必ず届く作りにする必要がある（推測）。
- **Webhook の2秒の問題**（候補欄、10-09 の調査）：今の作りはもともと Claude を待ってから応答しているので、アニメーションはこの問題を直さない。呼び出しの分だけわずかに長くなる（推測）。
- **燃やす・使い方**：固定文をすぐ返すので、アニメーションは要らない（推測）。
- **SAFETY**：触れる必要はない。危ない話を書いた人にも返事までの間に何か出るが、窓口の案内の代わりにはならない。
- **見えない人がいる**ため、「返事を待つ間は表示が出ます」と利用者に約束する書き方はできない（結論3）。

## 会社への示唆（3つ以内）

1. **企画部へ（実装候補になりうる。体験の改善）**：AI に回す発言のときだけ、Claude を呼ぶ前にローディングアニメーションを出す。`requirements.txt`・SAFETY・PERSONA・固定文・モデル・`max_tokens` は変えずに済み、外部アカウントも環境変数も要らない。失敗しても返事を止めない・例外の中身を出さない・送るのは ID と秒数だけ、をテストで見張る形なら、差分は100行に収まる見込み（推測。偽の SDK に1メソッドと1クラスを足す分を含む）。秒数は根拠がないので、省略時と同じ20秒か、検証記事の30秒あたりから企画部・安全審査部が決める（どちらも本番の待ち時間を見た数字ではない）。
