### 結論：10-05 から変わっていない（公式ページで確認）

## 2. LINE で1対1トークの内容がどこに残るか

ニュースの2026年分の一覧（`/ja/news/2026/`）は読めた。9月1日〜10月7日の告知は、料金改定、LIFF・LINEミニアプリの更新、デモアプリの提供終了、障害のお知らせ。**メッセージの保存・削除・送信取消・編集、トーク履歴の扱いを変える告知は見当たらなかった。**

- 関連しうる告知：**2026年10月6日 17:22頃〜17:30頃に LINE プラットフォームの障害**があり、Messaging API では Webhook イベントの送信が遅れたり、送られなかったりした（復旧済み）。9月15日深夜〜16日未明にも Messaging API の障害があった。
- 焚き火への当てはめ（推測）：障害で送信取消のイベントが届かなかった場合、その会話は焚き火のサーバーに残り、「燃やす」か、1時間以上あいて誰かが話しかけたときに消える。今の `HELP_TEXT` は送信取消に触れていないので、説明との食い違いはない。候補3で送信取消の一文を足すなら、「必ず消える」とは書かない方が安全。

#### 2-2. トーク画面（利用者の端末）

- 10-05 と同じ理解：ボットから送信済みのメッセージを消す機能は見当たらず、トーク画面の履歴は利用者が消さない限り残る。ただし、今日は Messaging API のリファレンスを再確認できていない（未確認）。
- LINE みんなの使い方ガイド「トークの送信取消機能」（ページの更新表示 2026年7月6日）：取り消したことは自分と相手の両方のトークルームに表示される。トークから削除したものは取り消せず、LINE が削除した情報を戻すこともできない。取り消せる期限と、公式アカウントとのトークでの扱いは、このページには書かれていなかった（未確認）。

#### 2-3. LINE 公式アカウント管理画面のチャット

- 管理画面のマニュアル「チャットの各種設定」（2025年10月30日更新）：チャット Pro オプションを買っている場合だけ、**「直近5年間のチャット履歴」** を CSV で書き出せる（週1回まで、10万チャットルームまで）。**チャットを使う設定にしている場合、管理画面側にはやり取りが長く残りうる**と読める（ただし保存期間そのものの説明ではない。推測を含む）。
- 「応答設定」（2026年3月25日更新）と「アカウント設定」（2026年4月24日更新）のマニュアルには、チャットをオフにした場合や Webhook だけで応答する場合に、管理画面にやり取りが表示・保存されるかの記述はなかった。**チャットをオフにしたときに管理画面に何も残らないかは、今日も未確認。**
- 参考（10-05 と同じ、二次情報・2022年12月）：チャットと Webhook を併用すると、管理画面にやり取りが表示される。

#### 2-4. LINE のサーバー（中継）

## 3. `WELCOME`／`BURN_REPLY` の言い方は言い過ぎか

### 3-1. 事実の整理（1・2 と `main.py` から）

| 場所 | 「燃やす」で消えるか | 根拠 |
| --- | --- | --- |
| 焚き火のサーバーの会話の記録（`sessions`） | **消える**（その場で） | `main.py` の燃やす処理で `sessions.pop` |
| 返事待ちの処理が持っている写し | **返事を送り終わるまで残る**（下記） | `main.py` の 246〜249行、259〜292行 |
| LINE のトーク画面 | 消えない | 2-2 |
| LINE 公式アカウント管理画面のチャット | チャットがオンなら残りうる。オフのときは未確認 | 2-3 |
| LINE のサーバー（中継） | 不明（未確認） | 2-4 |
| Anthropic | 消えない（通常は30日以内に削除。違反と判定されたら最長2年） | 1 |

**返事待ちの写しについて（`main.py` を読んで確認）**：Claude の返事を待っている間に「燃やす」を送ると、会話の記録（`sessions`）からはすぐ消える。しかし、返事を作っている処理は送る内容の写し（`to_send`）と履歴のリスト（`history`）を手元に持ったまま、Claude の返事を受け取って LINE に送るまで動き続ける。そのため、
- 燃やした直後の数秒ほどは、その処理の中に会話が残っている（記録し直されないことはテストで守られている）。
- 「燃やした」の返事のあとに、AI の返事がトーク画面に届くことがある。
秒単位のことで、ファイルなどに残るわけではない。ただ「もう残っていません」と言い切ると、厳密には正しくない場面がある。

### 3-2. 今の言い方の評価

- **`WELCOME`「話した内容はサーバーからぜんぶ消えます」：言い過ぎ。**
  - 「サーバー」が誰のサーバーか書かれていない。利用者は LINE や AI の提供元のサーバーも含めて受け取りうる（推測）。表の「消えない」に当たる場所がある。
  - 「ぜんぶ」がそれを強めている。10-05 の申し送りで避けると決めた「完全に消える」「どこにも残らない」に近く聞こえる（推測）。
  - `HELP_TEXT` は「焚き火のサーバーにある会話をその場で消します」と書いていて、言い方がそろっていない。
- **`BURN_REPLY`「今の話はサーバーにはもう残っていません」：言い過ぎ。** `WELCOME` と同じく「サーバー」が誰のものか書かれていない。さらに「もう残っていません」は、3-1 の返事待ちの写しがある場面では厳密には正しくない。
- `BURN_REPLY` の「……ぜんぶ燃えて灰になりました」はたとえで、何が消えたかを言ってはいない。ただ、すぐ次の文で範囲を絞らないと、「ぜんぶ」が利用者に広く伝わりうる（推測）。

### 3-3. 文言案（材料。決めるのは企画部）

守ること（10-05・10-07 の申し送り）：「完全に消える」「どこにも残らない」「1時間で消える」「自動で消える」と書かない。「焚き火のサーバーから消える／トーク画面には残る」の書き分けを崩さない。`WELCOME` には「使い方」の語を残す（`tests/test_main.py` の338行目が確認している）。`BURN_REPLY` の文言を変えても、既存のテストは `main.BURN_REPLY` そのものと比べているので壊れない（`tests/test_main.py` を読んで確認）。

**`WELCOME` の3行目（今：「スッキリしたら「燃やす」で、話した内容はサーバーからぜんぶ消えます。」）**

| 案 | 文言 | 特徴 |
| --- | --- | --- |
| W-A（最小の修正） | スッキリしたら「燃やす」で、話した内容を焚き火のサーバーから消します。 | `HELP_TEXT` と同じく「焚き火のサーバー」に絞る。「ぜんぶ」を外す。次の行の「何が消えて何が残るか」へ自然につながる |
| W-B（残るものを一言だけ） | スッキリしたら「燃やす」で、焚き火のサーバーにある会話を消します（LINEのトーク画面には残ります）。 | 最初のあいさつで誤解の余地をいちばん減らせる。そのぶん1行長い |
| W-C（言い回しを今に近く） | スッキリしたら「燃やす」で、焚き火のサーバーにある会話はぜんぶ消えます。 | 今の調子を残す。「ぜんぶ」が残るので、返事待ちの写し（3-1）があることを考えると W-A／W-B より強い言い方になる |

**`BURN_REPLY` の3行目（今：「今の話はサーバーにはもう残っていません。今日もおつかれさま。」）**

| 案 | 文言 | 特徴 |
| --- | --- | --- |
| B-A（最小の修正） | 今の話は、焚き火のサーバーから消しました。今日もおつかれさま。 | 「消しました」は焚き火がした操作（`sessions` から消す）を言うので、返事待ちの写しがある場面でも事実と合う |
| B-B（トーク画面に触れる） | 焚き火のサーバーにあった今の話は、消しました。トーク画面の履歴は残るので、気になるときは「使い方」を見てね。今日もおつかれさま。 | 燃やすたびに「残るもの」を思い出してもらえる。長くなり、燃やしたあとの余韻は弱まる（推測） |
| B-C（たとえを残して範囲を絞る） | ……燃えて灰になりました。（2行目の「ぜんぶ」を外す）＋ B-A の3行目 | たとえの「ぜんぶ」も外して、言い方を全体で控えめにそろえる |

- 返事待ちの間に燃やすと AI の返事があとから届くこと（3-1）を説明文に書くかは、企画部の判断。書かなくても、B-A の「消しました」なら言い過ぎにはならない（推測）。

## 会社への示唆（3つ以内）

1. **`HELP_TEXT` は直さなくてよい。** Anthropic の保持期間（30日以内）、例外（違反と判定されたら最長2年）、学習利用（既定では使わない）は、公式ページの更新日も中身も 10-05 と同じ。LINE 側も、変わったという告知は見つからなかった。ただし、LINE Developers の本文とプライバシーポリシーは今日は再確認できていない。次回の見直し（月1回）では、これらと編集イベントの対象（1対1に届くか）を優先して確かめる。
2. **`WELCOME` と `BURN_REPLY` は言い過ぎなので、候補3として直すことを勧める。** 理由は二つ。「サーバー」がどのサーバーか書かれていないため、LINE や Anthropic のサーバーを含むように読めること。`BURN_REPLY` の「もう残っていません」は、返事待ちの間に燃やした場面では厳密には正しくないこと。最小の修正は W-A と B-A。どちらも、焚き火がしたこと（焚き火のサーバーから消した）だけを言う。文言だけの変更で、既存のテストは壊れない。
3. **`docs/owner_todo.md` の「管理画面のチャットをオフに」の確認は今も大事。** チャットを使う設定だと、管理画面に直近5年分の履歴が残りうる（チャット Pro の書き出し機能からの推測）。チャットをオフにしたとき何も残らないかは、公式の文書では今日も確認できていない。
