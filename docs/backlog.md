### LINE への返信が失敗しても例外を `/callback` まで上げない＋届かなかった1往復を履歴から外す

根拠：`docs/research/2026-10-09.md` の 1-1、1-3、2-1、2-3 と示唆1（候補「LINE への返信が失敗したときの扱い」の判断材料）。分類：体験の改善（利用者が見ていない返事を前提に次の会話が進むのを防ぐ）＋お客さまとの約束を守る仕組み（未処理の例外で、エラーの詳細がサーバーのログに出るのを防ぐ。今出ているかは会社から見えないので未確認）。LINE SDK に新しく依存しない（`except Exception` で受け、SDK の例外クラスは import しない）。

#### なぜこれを選んだか（安全フラグの件との比較）

- **安全フラグの件（応援リンクの第一候補）を今日は選ばない理由**：
  1. `SUPPORT_URL` 未設定の今の本番には影響がない。オーナーには「直すまで設定しない」とお願いを続けている。
  2. 10-08 に見つけた穴（燃やした直後で新しい会話がまだないときに相談先の案内が届く場合）は、(a) 防げる範囲だけ直す、(b) 返事待ち中に燃やしたら燃やす返事に応援リンクを出さない、のどちらにするかが決まっていない。安全審査部と方式を決める前に作ると、差し戻しかやり直しになりやすい。「迷う変更は出さない」に当たる。
  3. 今日の調査は返信の失敗についてのもので、安全フラグの方式を決める新しい材料はない。
- **返信の失敗を選ぶ理由**：
  1. 調査で判断材料がそろった。再送は初期設定でオフ、reply token は1回きり・1分以内、再送でも元の token が使用済みなら使えない。再送がオフなら、握りつぶしても利用者から見た結果（何も届かない）は今と同じ。再送がオンなら、握りつぶして 200 を返す方が、Claude の二重呼び出し（料金2回分）や同じ発言の重複を防げる。**どちらの設定でも、今より悪くならない**（推測を含む。調査 2-3）。
  2. 今は返信に失敗しても、利用者が見ていない AI の返事が履歴に残り、次の返事がそれを前提に進む（コードから）。外せば「届かなかった1往復はなかったこと」になる。
  3. 本体はおおむね15行で、`reply()` 1か所と `on_message` の終わりだけを触る。10-06〜10-08 のコミットとは別に戻せる。
- **迷う要素の評価**：本番で返信がどのくらい失敗しているか、再送がオンかは会社から見えない。ただし上のとおりどちらでも害が増えない形にできるので、「迷うから出さない」ほどではないと判断した。2秒のタイムアウト（調査 2-2）と重複イベント（`webhookEventId`）は今日の変更では直らない（別の候補に分ける）。

#### 目的（お客さまにとって何が良くなるか）

- 返事が LINE に届かなかったとき、その1往復（自分の発言と届かなかった AI の返事）が履歴に残らない。次に送ったとき、見ていない返事を前提にした話にならない。
- 再送がオンになっていても、返信の失敗をきっかけに同じ発言が二重に処理されることがなくなる（オーナーの料金も守る）。
- 返信の失敗で未処理の例外が出なくなり、例外の中身（LINE の応答本文など）がログに出る道が1つ減る。代わりに出すのは、会話を含まない決まった一行だけ。
- 安全フラグは残す（危ない言葉・相談先の目印で立ったフラグは、返信が失敗しても下ろさない）。応援リンクが出ない条件は変わらない。
