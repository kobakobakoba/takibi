### 危ない言葉の照合の前に、文字をそろえる（半角カナ→全角カナ→ひらがな）。一覧の50語は変えない

根拠：今日の調査（`docs/research/2026-10-15.md` の 1・2、示唆1・2）と、10-13 の安全審査部の意見（「一覧はこれ以上大きくしない方針が望ましく、照合前に文字をそろえる方法は別の日に1つの変更として出す」）、10-14 の日報（「これ以上広げるより、絞り込みや、カタカナをひらがなにそろえる案を先に検討する」）。分類：**安全性の改善**（最優先）。SAFETY ブロックの外。標準ライブラリ（`unicodedata`）だけで、`requirements.txt` は変えない。`main.py` おおむね12行＋テスト おおむね45行。**安全審査部の承認が要る**（危ない言葉の判定の仕組みを変えるため、承認がなければ出さない）。

#### なぜこれを選んだか

- **拾える範囲を広げる（安全側の）変更で、一覧を大きくしない**：一覧の50語は一字も変えずに、ひらがなの形がある17語（`しにたい`・`きえたい`・`しにたく`・`たたいてしま`・`しんじゃいた` など）で、カタカナ（「シニタイ」）、半角カナ（「ｼﾆﾀｲ」）、漢字とカタカナの混ざった形（「死ニタイ」）も拾えるようになる（調査 2-2）。カタカナ形を1語ずつ足すと一覧が67語になるが、これなら1語も増えない。今後ひらがなの語を足すたびに、カタカナ形も自動で拾える。
- **小さく、元に戻しやすい**：関数1つと、照合2か所を同じ関数の呼び出しに置き換えるだけ。データも環境変数もない。
- **`しにたく` の絞り込みは今日も選ばない**：拾える範囲を狭める変更なので、安全審査部が「拾えなくなる言い方」を受け入れるかの判断が先（10-14 の方針どおり、足す変更とは別の日に単独で）。今日の変更は「足す」側なので、混ざらない。
- **効き目は「起きたときの守り」**：当事者がカタカナで書く頻度は出典で確かめられなかった（調査 2-3）。日報では効き目を大きく言わない。
- **スタンプのひとこと（体験の改善）は今日も選ばない**：v3 の振り分けの順番が未確認のまま。

#### 目的（お客さまにとって何が良くなるか）

- 「シニタイ」「ｼﾆﾀｲ」「死ニタイ」「キエタクナル」「タタイテシマッタ」「ｼﾝｼﾞｬｲﾀｲ」のように、カタカナや半角カナで打った人にも、ひらがな・漢字で打った人と同じ守りが届く：運悪く AI が答えられなくても、おわびと一緒に「命や安全が今まさに危ないときは、110番・119番へ。」が届く。燃やした後に応援リンクを出さない（`SUPPORT_URL` を設定した日から効く）。
- AI に送る文、会話の履歴は**送られたままの文**で、書き換えない。そろえた文はその場の判定にだけ使い、どこにも残さない・ログに出さない。
- 「ワンオペで疲れた」「ケアマネに電話した」のような、カタカナ語を含む普通の愚痴は今までどおり。AI の普段の返事や SAFETY ブロックの指示は変わらない。

```python
_KATA2HIRA = {c: c - 0x60 for c in range(0x30A1, 0x30F7)}


def fold_kana(text: str) -> str:
    """半角カナ→全角カナ（NFKC）→ひらがな。空白・「ー」・記号は消さない。元の文は変えず、結果はどこにも残さない"""
    return unicodedata.normalize("NFKC", text).translate(_KATA2HIRA)


def has_safety_words(text: str) -> bool:
    """SAFETY_USER_WORDS に当たるか（部分一致）。そろえた文はこの中だけで使う"""

```
