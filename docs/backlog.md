### 応援リンク（収益化 第1段階）：燃やしたあとに、条件を満たすときだけ一言添える

根拠：`docs/research/2026-10-04.md`（調査部の提言1・2）。

> 結果：実装・本番反映済み（テスト22本合格、安全審査は1回差し戻し→承認）。差し戻しを受けて `SAFETY_USER_WORDS` にひらがな・関連語（しにたい、きえたい、しのう、死んだほうが、いなくなりたい、傷つけ、虐待、限界、首を絞め、殴）を追加したため、下の定数案より実装のほうが広い。最新は `main.py` を参照。

#### 目的（お客さまにとって何が良くなるか）

- 余裕があって「応援したい」と思った人だけが、その気持ちを形にできる。
- 応援しない人には何も変わらない。命や安全の話をしたあとにお金の話が並ぶことはない。罪悪感をあおる言い方もしない。
- オーナーが `SUPPORT_URL` を設定するまでは、今と全く同じ動きをする。

#### 表示の条件（すべて満たすときだけ出す）

1. 「燃やす」と送ったときだけ。会話の途中の返事には出さない。
2. 環境変数 `SUPPORT_URL` が設定されていて、前後の空白を取り除いた値が `https://` で始まる。それ以外（未設定、空、`http://`、`javascript:` など）は何も出さない。
3. 燃やした会話が存在し、ユーザーの発言が1つ以上ある（会話なしでいきなり「燃やす」と送った場合は出さない）。
4. その会話の中で「安全フラグ」が立っていない（下記）。

#### 安全フラグの設計（会話の内容を保存しない）

- `sessions[user_id]` に、会話内容ではなく真偽値1つ `"safety": True` だけを足す。どの言葉に反応したかは記録しない。
- 立てるタイミング：
  - ユーザーの発言を受け取った時点（Claudeを呼ぶ前）。発言に `SAFETY_USER_WORDS` のどれかが含まれていたら立てる。APIが失敗した場合でも立つ。
  - Claudeの返事を受け取った時点。返事に `SAFETY_REPLY_MARKERS` のどれかが含まれていたら立てる（SAFETYブロックが反応して相談先を案内したことの目印）。
- フラグは会話と一緒に消える。「燃やす」で `sessions.pop` したとき、1時間放置で会話が作り直されたとき、サーバー再起動時。燃やしたあとに残るものは何もない。
- 判定に迷う語は「出さない」側に倒す（誤って立っても、応援リンクが出ないだけで害はない）。
- **`SAFETY` ブロック（51〜59行目）には一切触れない。** 目印の言葉は、ブロックの外に新しい定数として置く。

定数案（`SAFETY END` の行より後、`SYSTEM_PROMPT` の近くに置く）：

```python
# 応援リンクを出さないための目印（SAFETYブロックの外。会話内容は保存せず、真偽値だけ立てる）
SAFETY_USER_WORDS = ["死にたい", "消えたい", "死のう", "自殺", "自分を傷つけ", "叩いてしまい", "手が出", "殺し"]
SAFETY_REPLY_MARKERS = ["まもろうよ", "189", "親子のための相談", "地域包括支援センター", "ケアマネ", "110", "119", "相談窓口", "いのちの電話"]
```

#### 文言案（固定。Claudeには作らせない）

```python
SUPPORT_NOTE = (
    "\n\n――\n"
    "焚き火はこのまま無料で使えます。\n"
    "もし余裕があって応援したいと思ったときだけ、こちらからどうぞ。"
    "（応援先のサービスには、お名前などが届く場合があります）\n"
)
```

- 表示は `BURN_REPLY + SUPPORT_NOTE + url` の1通。メッセージを2通に増やさない。ボタンも付けない。
- 「続けるには応援が必要」「無料で使い続けるのは…」のような罪悪感を使う言い方は入れない。

#### 変更内容（どのファイルの何を変えるか）

`main.py`（約30行）：

1. 上記の `SAFETY_USER_WORDS`、`SAFETY_REPLY_MARKERS`、`SUPPORT_NOTE` を追加。
2. `support_url()` 関数を追加：`os.environ.get("SUPPORT_URL", "").strip()` を毎回読み、`https://` で始まればそれを、そうでなければ `""` を返す（テストで環境変数を切り替えられるよう、起動時に固定しない）。
3. `on_message` の燃やす処理を変更：`s = sessions.pop(user_id, None)` で取り出し、`url` があり、`s` があり、`s["messages"]` にユーザー発言があり、`not s.get("safety")` のときだけ `BURN_REPLY + SUPPORT_NOTE + url` を返す。それ以外は今まで通り `BURN_REPLY`。
4. `on_message` の通常処理：`get_history` の直後に、発言が `SAFETY_USER_WORDS` を含めば `sessions[user_id]["safety"] = True`。Claudeの返事を受け取ったあと、返事が `SAFETY_REPLY_MARKERS` を含めば同じく `True`。
5. 触らないもの：`SAFETY` ブロック、`PERSONA`、モデル、`max_tokens`、`requirements.txt`、起動コマンド。ファイル書き込み・ログ出力は追加しない（`print`/`logging` で会話や判定結果を出さない）。

#### リスクと戻し方

- リスク1：目印の言葉が漏れて、SAFETY反応後にリンクが出てしまう。→ 返事側の目印（相談先の名前・番号）とユーザー側の言葉の両方で判定し、迷う語は出さない側に倒す。
- リスク2：誤判定でリンクが出にくくなる。→ 害はない（収益が少し減るだけ）。許容する。
- リスク3：毎回出てしつこく感じる。→ 今回は回数制限を見送った（下の候補2を参照）。文言を固定・控えめにして影響を抑える。
- 戻し方：すぐ止めたいときは、オーナーがRenderで `SUPPORT_URL` を消すだけ（コード変更不要、初期状態に戻る）。コードごと戻すときは該当コミットを `git revert`。

#### 今回見送ったこと

- **1日1回までの回数制限**：実現するには、燃やしたあとも「この人は今日リンクを見た」という記録（ユーザーIDと日付）をメモリに残す必要がある。会話内容ではないが、「燃やしたら消える」の約束と緊張するため、今日は入れない。安全審査部の判断を仰いでから別の日に検討する。

## 候補（優先度順）

1. **ヘルプ／プライバシーの説明**：「使い方」と送ると、燃やす仕組み、「サーバーに残らない」こと、LINEのトーク画面には履歴が残ること、応援した場合は名前やメールが応援先サービスに届くこと、を説明する。（約束を守る仕組み。応援リンクの公開に合わせて早めに）
2. **応援リンクの出しすぎ防止**：1日1回までなどの上限。燃やしたあとに何も残さない方法（例：上限ではなく「ユーザーの発言が3つ以上あった会話のあとだけ」など、記録不要の条件）を先に検討し、記録が要る案は安全審査部の判断を仰ぐ。
3. **1日の利用回数の上限**：環境変数 `DAILY_LIMIT` が設定されていれば、1人1日その回数まで。上限に達したら優しく伝える。コスト対策と、有料プランの土台。（収益化 第2段階の準備。回数の記録が要るため、候補2と同じ論点あり）
4. **同時アクセスの安全性**：会話の入れ物を、複数スレッドから同時に触っても壊れないようにする。（安全審査部の申し送り：返事待ちの間に「燃やす」が来ると `sessions[user_id]` で KeyError になり得る。変更前からある問題）
5. **長文の分割**：LINEの文字数上限を超える返事を安全に切る。
6. **育児／介護のモード分け**：最初のあいさつで「育児」「介護」のボタンを出し、選んだほうに合わせて受け止め方を少し変える（例：介護なら終わりの見えなさ、育児なら睡眠不足への共感）。
7. **夜間モード**：深夜（日本時間0〜5時）は、より短く静かな返事にする。寝かしつけや夜間介護中の人向け。
