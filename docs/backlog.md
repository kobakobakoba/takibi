## 今日の改善（2026-10-08）

### AI の返事が空（または空白だけ）なら、API失敗と同じ扱いにして「もう一度送ってみて」を返す

根拠：`docs/research/2026-10-08.md` の 2-4 と示唆3（調査部の新候補）。分類：安全性の改善（つらい話を送った人に何も返らない「無言」を防ぐ）＋体験の改善（会話が壊れて以後ずっと失敗し続けるのを防ぐ）。LINE SDK に新しく依存しない。

#### なぜこれを選んだか（ほかの候補との比較）

- 今のコードを読むと、Claude の返事にテキストがない、または空白だけのとき、`answer` が `""` になる。このとき次の2つが起きうる（コードを読んでの指摘。起きる頻度は会社から見えないので未確認）。
  1. 空の `{"role": "assistant", "content": ""}` が履歴に入る。Anthropic API は空のテキストを受け付けない可能性が高く（推測）、そうなると**その人の次の発言からは毎回 API 失敗の「火の調子が悪い」になり、「燃やす」か1時間放置するまで直らない**。
  2. `TextMessage(text="")` を LINE に送ろうとして例外になる可能性が高い（推測。調査 2-4）。利用者には**何も返らない**。死にたい・叩いてしまいそうと書いた人に無言が返るのは、焚き火でいちばん避けたい形。
- 直し方は、空なら try の中で例外を投げて、**すでにある API 失敗の処理（自分の発言だけ履歴から外し、決まったおわびを返す）にそのまま乗せる**だけ。本体3行で済み、10-07 のロックの形も崩さない。
- 「応援リンクを有効にする前に必ず直す（安全フラグの件）」は、`SUPPORT_URL` 未設定の今は影響がなく、オーナーにも「直すまで設定しない」とお願い済み（10-06 日報）。一方こちらは**今の本番に効く**。また安全フラグの件は、読み直すと「燃やしたあと、新しい会話がまだない間に相談先の案内が届く」場合は、燃やしたあとも何かを覚えておかない限り直せない（候補欄に追記）。どこまで直すかを安全審査部と詰める必要があるので、別の日に単独で出す（次の第一候補のまま）。
- 2つをまとめると、どちらも Claude 呼び出し後の同じあたりを触るうえ、片方だけ戻したいときに戻しにくい。今日は1つに絞る。
- 長文の分割（候補7）は、調査で「`max_tokens=400` と2〜4文の指示では上限に届きにくい（推測）」となったので下げる。

#### 目的（お客さまにとって何が良くなるか）

- AI がうまく返事を作れなかったときも、無言にならず「ごめん、いま火の調子が悪いみたい。少ししてからもう一度送ってみて。」が返る（燃やすボタン付き。今の API 失敗時と同じ）。
- 空の返事が履歴に残らないので、次に送ったときは普通に受け止めてもらえる。
- 安全フラグ（発言に危ない言葉があったら立てる）は Claude を呼ぶ前に立つので、今回の変更後も残る。応援リンクが出ない条件は変わらない。
