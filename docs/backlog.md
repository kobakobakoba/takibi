## 今日の改善（2026-10-12）

### おわび（API 失敗・空の返事）に、危ない言葉があった会話のときだけ「110番・119番」の一文を添える

根拠：候補「おわびの文言の見直し」（10-08 の企画部のリスク2、安全審査部の申し送り 10-08）。今日、社長が安全審査部に事前相談し、**案A可**の回答を得た（案B「常に添える」は不可）。安全審査部の回答で「会社の判断で本番に出してよい（日報で報告）」とされたので、オーナーの確認は待たない。分類：**安全性の改善**（最優先）。LINE SDK に新しく依存しない、`main.py` おおむね8行＋テスト8本。

#### なぜこれを選んだか

- **安全性の候補で、今日作れる唯一のもの**：「死にたい」などを送った直後に API が落ちる・空の返事になると、今は「火の調子が悪い」のおわびだけが届き、相談先の手がかりが何も出ない。安全審査部の回答で作り方（案A）と必須テストが決まった。
- **スタンプのひとこと（体験の改善）は今日は選ばない**：今日の調査（`docs/research/2026-10-12.md`）で「新しい import なしで作れる見込み」は立ったが、(1) v3 の振り分けの順番は今日も v3 本体を読めず未確認、(2) メッセージスタンプの `text` に利用者の言葉（「しにたい」など）が入りうる点の扱いを安全審査部がまだ判断していない。安全の判断が残るものを、安全の判断が済んだものより先に出す理由はない。1日1つの原則で、案Aを先に出す。
- **小さく、元に戻しやすい**：処理の流れは変えず、おわびの文に一文を足すかどうかの分岐だけ。

#### 目的（お客さまにとって何が良くなるか）

- 「死にたい」「手が出そう」など危ない言葉を送ったときに、運悪く AI が答えられなくても、おわびと一緒に「命や安全が今まさに危ないときは、110番・119番へ。」が必ず届く。返事がない・おわびだけで突き放される、ということがなくなる。
- 危ない言葉がない普通の愚痴のときは、おわびは今までどおり。必要のない人に緊急の案内を見せて驚かせない。
- 応援リンクはおわびには絶対に付かない（今までどおり）。
